## Development

```sh
npm run typecheck         # tsc --noEmit
npm test                  # vitest
npm run test:integration  # vitest against a document server in docker
npm run lint              # eslint
npm run format            # prettier --write
npm run build             # tsup -> dist (ESM + CJS + .d.ts), one entry per subpath
npm run check:exports     # the built subpaths share every export with the root
npm run docs              # typedoc -> docs/api (markdown API reference)
```

## Modules

A module is a folder under `src/` with an `index.ts`. The folders are the one list of modules:
the build takes `src/*/index.ts`, the package exports `./*` onto what it built, and the API
reference documents the same files.

To add a module, create its folder and add a line to `src/index.ts`. `npm run check:exports`
fails when the line is missing, or when `dist/` has a folder no module stands for.

The client and the format lookup each declare `Format`, and the root exports the one of the
lookup. The two are the same type, and a test keeps them so.

## Documentation

- `README.md` is the entry point: installation and the quick start.
- `docs/guides/` explains one task per guide. Start a section with code, then the details.
- `docs/api/` is generated from the doc comments by [TypeDoc](https://typedoc.org). The exact
  contract of a type or a method belongs in its doc comment.

The API reference is committed, so a change to the public API is reviewed with the code that
made it. Run `npm run docs` after changing an exported type or a doc comment; CI fails when
`docs/api/` is out of date.

## License header

Every source file starts with the Apache 2.0 header of Ascensio System SIA, which
`eslint-plugin-license-header` checks. The header is written out in `eslint.config.js`, with the
current year. So the first lint of a new year fails on every file until `npm run lint:fix`
rewrites the headers.

The module entries, `src/*/index.ts`, end the header with `@license Apache-2.0`. TypeDoc skips a
comment with that tag and reads the `@module` comment after it. Otherwise it would take the
header for the description of the module.

## Integration tests

`npm run test:integration` runs the tests under `test/integration/` against a real document
server instead of a mocked `fetch`. It starts `docker-compose.integration.yml` (the document
server with a JWT secret, and an nginx that serves `test/integration/fixtures/` for the server to
download), waits for `/healthcheck`, runs the tests and stops the stack.

The tests cover what can be checked without an open editor: the server configuration and
formats, conversion by URL and from a file, the command service, the document builder,
downloading the results, and tokens in the body and in a header.

They also check:

- the tokens the document server signs: a server in the test process serves files the document
  server downloads, and `verifyHeader()` reads the token of that download. The document server
  reaches it as `host.docker.internal`, which `extra_hosts` maps to the host on Linux too;
- that `getFormats()` names no type or action unknown to `FormatType` and `FormatAction`, so a
  newer server that adds one fails the run;
- that a timeout and an unreachable server reject with the errors of the SDK.

Environment variables:

| Variable          | Default                       | Does                                                         |
| ----------------- | ----------------------------- | ------------------------------------------------------------ |
| `DOCS_URL`        | —                             | a document server already running; the stack is not started  |
| `DOCS_JWT_SECRET` | `integration-secret`          | the secret of that server                                    |
| `FIXTURES_URL`    | `http://fixtures`             | where that server downloads the fixtures from                |
| `HOST_URL`        | `http://host.docker.internal` | where that server reaches the test process, without the port |
| `DOCS_KEEP`       | —                             | leaves the stack running after the tests, for the next run   |

Without `DOCS_URL` the tests reach the server at `http://localhost:8080`, so the port has to be
free.
